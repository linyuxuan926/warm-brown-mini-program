# 首页空白与组件加载错误修复记录

修复日期：2026-11-03。

## 报错与直接原因

日志中的 `Component is not found in path` 涉及三套首页 `home-cat`、`home-cloud`、`home-dog`，以及点单页的 `spec-sheet`、`cart-sheet`。首页外层、主题选择和底部导航由页面自身渲染，主体由自定义组件渲染，因此出现了“可以切换风格，主体却空白”的现象。

五个组件的 JS、JSON、WXML、WXSS 均存在，`component: true`、`Component()` 注册与页面引用路径有效。实际开发者工具完整重新编译后，首页恢复。对照中重新启用按需加载仍可显示，所以不能认定 `lazyCodeLoading` 是唯一根因。

继续操作发现开发者工具 **1.06.2504030** 中，真实鼠标点击风格页后，导航标题和页面路径已更新，画面却仍残留猫咪首页，自动化页面查询也不正常。基础库 **3.17.2** 与 **3.11.3** 的对照中都出现过画布残留，调整窗口尺寸后立即重绘。检查进程确认工具仍携带此前排查白窗时添加的 `--disable-gpu` 参数，因此不能把基础库版本单独认定为根因。修复包括恢复正常工具启动方式；最终项目使用固定基础库 **3.11.3** 进行复测。

## 已实施修复

- 移除 `miniprogram/app.json` 的 `lazyCodeLoading: "requiredComponents"`，采用默认加载方式。
- 在 `project.config.json` 显式设置 `setting.ignoreDevUnusedFiles: false`，关闭开发编译的未使用文件裁剪。约 400 KB 的项目无需依赖这项优化，完整开发包便于排查组件注册问题。这是兼容性加固，不是已证实的单独根因。
- 在同一配置中固定 `libVersion: "3.11.3"`，保持复测环境一致。
- 恢复开发者工具“通用设置 → 启动设置 → 使用 GPU 加速模式”，并正常重新启动。工具会把 `--disable-gpu` 参数持久化为关闭 GPU；只在下次命令中去掉参数不足以恢复，需要同时恢复这项设置。
- 重新完整编译，验证实际模拟器视图。
- 将五个组件中的标签、属性选择器改为组件类名；两个弹层采用独立的组件样式，避免导入全局页面样式产生 `Some selectors are not allowed in component wxss` 警告。
- 增加组件文件、注册执行、依赖与 WXML 标签检查，并增加三套首页模板输出及损坏组件回归用例。

这次修复未修改业务存储结构，不需要重置订单、余额、地址或购物车。

## 本地使用

开发者工具打开项目根目录（包含 `project.config.json` 的目录），确认“详情 → 本地设置”使用基础库 **3.11.3**，点击“编译”或按 `Ctrl+B`，让当前运行包采用修复后的配置。若另一台电脑仍沿用旧内容，可只清理开发者工具的编译/文件缓存后重新编译；保留数据缓存即可保留本地业务记录。

## 其他日志的含义

`41002 / webapi_getwxaasyncsecinfo:fail appid missing` 来自游客 AppID 下的微信平台安全信息查询。项目没有调用这个接口。当前保留 `touristappid`，没有伪造或替换用户的真实身份；要消除这类平台身份错误，需要在开发者工具中使用微信提供的测试号或你自己的有效小程序 AppID。

`preloaded using link preload but not used` 是开发者工具内部资源预加载提示，不是本次组件主体空白的原因。

33 项自动化测试全部通过，5 个组件的文件和注册检查通过；21 个 WXML、24 个 WXSS 编译通过。原生运行结果、工具版本与截图见 [测试记录](TEST_RECORD.md)。

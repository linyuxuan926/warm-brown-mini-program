## 自动化覆盖

业务测试实际覆盖：

1. 初始分类、商品数量、每类数量、邮寄数量、售罄、账目余额、地址与订单筛选数据。
2. 必选规格、同规格合并、不同规格价格、非法数量与售罄限制。
3. 履约不兼容时阻止直接切换，确认后仅移除不兼容行。
4. 四种履约从建单、支付到完成的合法状态；自取码和虚构运单；首次完成积分。
5. 建单 token 防重、待支付占库存、取消释放、重复支付不重复扣库存。
6. 失败与取消支付保留待支付订单及券占用；取消订单释放券。
7. 券门槛、品类、履约、过期、单券限制；运费门槛和地区校验。
8. 联系人、手机号、桌号、取餐时间、地址格式与事务不变性。
9. 模拟充值幂等、余额支付及流水一致性；余额不足保持原状态。
10. 领取幂等、积分兑换与扣分流水；地址默认唯一及历史地址快照。
11. 再次购买按当前数据校验，历史快照不变；搜索与分类组合行为。
12. 冷启动持久化、主题不影响业务、存储失败回滚、旧版迁移、缺失会员字段的默认值修复与损坏实体恢复。

- 四条完整流程：**首页带方式 → 点单与搜索 → 必选规格、大杯加价及数量 → 购物车 → 地址/桌号 → 选券 → 提交防重 → 支付失败与取消 → 重试成功 → 成功页 → 订单推进与积分 → 三套主题共享数据**。

## 空白首页的排查与原生环境验收

实际安装位置为 `D:\大\文件\微信web开发者工具\cli.bat`，工具版本 **1.06.2504030**。`project.config.json` 固定基础库 **3.11.3** 作为复测环境，控制台调用栈也确认实际加载该版本。该配置不代表已证实基础库是本次故障的根因。

本轮已确认旧运行状态缺少 `home-cat`、`home-cloud`、`home-dog`、`spec-sheet`、`cart-sheet` 五个自定义组件的注册。页面外层仍正常渲染、风格选择仍能保存，无法加载的组件内容却是空白，这与用户提供的截图和 `Component is not found` 日志吻合。源码中的组件四件套和 `Component()` 定义有效。完整重编后首次恢复的猫咪画面见 [`after-config-runtime.png`](../artifacts/screenshots/after-config-runtime.png)，但后续实际界面操作发现该阶段仍存在导航重绘问题，不能只凭初始首页图认定修复完成。

基础库对照的后续复查修正了早期判断：工具在 **3.17.2** 和 **3.11.3** 下均曾出现导航标题、路径已改变，但可见画面残留旧页面的现象。调整工具窗口大小后可以恢复重绘；[`native-library3113-style.png`](../artifacts/screenshots/native-library3113-style.png) 记录了恢复后的真实主题页，不能据此断言换库已消除问题。因此撤回将 `3.17.2` 单独归为兼容根因的结论，保留 `3.11.3` 作为固定复测条件。

进一步检查确认：此前为诊断工具白窗而使用的 `--disable-gpu` 会被工具迁移逻辑持久写为全局设置 **`general.enableGPU=false`**。之后即使 CLI 命令没有该参数，工具仍会读取这个设置并自动附加 `--disable-gpu`。修复仅恢复该布尔值并正常重启，已核对最终主进程没有该参数。随后真实点击主题页、返回首页、规格与购物袋均自然完成重绘，无需缩放窗口；切页等待约 2 秒后核对最终画面。其余工具配置、订单、余额和地址保留。

用户可在工具界面「**设置 → 通用设置 → 启动设置 → 使用 GPU 加速模式**」启用该选项并按提示重启。组件注册/编译缓存和桌面画布重绘分别记录，不能以路径变化、初始首页截图或自动化数据返回替代实际界面重绘验收。

排查中也进行了按需加载配置的启用、停用及重新启用测试。重新启用并重启后初始首页仍可显示，因此证据不支持将 `lazyCodeLoading` 单独认定为必然根因。最终保留默认组件加载方式，并在固定基础库后完整重新编译。组件专项检查用于识别源码缺陷，最终是否加载成功以当前开发者工具运行结果为准。

`project.config.json` 显式设置 `setting.ignoreDevUnusedFiles: false`，在开发包中保留依赖文件，作为开发环境兼容性加固。此配置也没有被单独证实为本次故障的根因。

组件 WXSS 中不允许的标签选择器已改为类选择器，并补充组件内基础样式，使样式符合组件隔离规则。修复后已重新运行全部 33 项测试、项目结构/组件检查和 21 个 WXML / 24 个 WXSS 编译检查，全部通过。最终开发者工具完整编译见 [`native-final-compile.png`](../artifacts/screenshots/native-final-compile.png)：实际 `WeChatLib 3.11.3`、`LazyCodeLoading: false`，**0 errors**，没有 `Component is not found` 或组件 CSS 选择器警告；仅有两项工具系统警告，分别涉及 SharedArrayBuffer 与 getSystemInfo 提示。

早前游客启动的五项 `error` 已逐项确认均为 `touristappid` 触发的平台 **41002 / AppID 缺失**提示，见 [`native-console-diagnostic2.png`](../artifacts/screenshots/native-console-diagnostic2.png)。最终编译未再出现这些错误，但不能据此宣称更换基础库修复了平台身份或已取得正式 AppID 权限；游客条件下仍可能出现该类平台提示。测试期间还发现过 CLI 自动化残留的「更改 AppID 失败」工具弹窗，其会阻挡编译与界面操作，已与页面业务错误区分。本轮没有真机验收结论。

原生自动化桥接限制：`App.getCurrentPage` 曾无响应，替代自动路由验证也出现逻辑上下文与可见模拟器视图不同步。历史 [`native-report.json`](../artifacts/screenshots/native-report.json) 和本轮中间 [`component-regression-report.json`](../artifacts/screenshots/component-regression-report.json) 均保留失败状态，不能改写为成功报告。最终原生视图验收采用真实界面点击和画面核对，自动化的处理函数、数据或路径结果不单独作为画面已正确重绘的证据。

## 已知限制

- 仅本机持久化，无生产服务器、真实身份验证、多用户隔离或跨设备同步；清除缓存会清除数据。
- 门店、地址、联系电话、物流与配送范围均为虚构；无实时地图、物流、商户或骑手接口。
- 无真实微信支付、退款、发票、自动超时关单或运营后台；仅待支付可取消。
- 原创图片已本地化并使用 PNG，但无破图、文字溢出、弹层滚动和所有机型安全区仍需原生视图验收。
- 游客 AppID 供本地演示；真机预览/上传/发布需使用自己的有效 AppID 及微信平台权限。
- 旧版 `wcc/wcsc` 仅增加模板与样式语法证据，最终以当前开发者工具和目标基础库为准。

# 暖棕小屋 · 3–5 分钟答辩演示

## 演示前

在微信开发者工具导入项目根目录 `D:\大\小程序期末` 并编译。打开「我的 → 重置演示数据」，两次确认。确认底部有首页、点单、订单、我的四个原生入口。

以下主流程使用初始数据：余额 120 元、积分 320、`coupon-1` 午后小确幸券未使用。不要先消耗该券；若已操作过，先重置。

## 主流程

| 时间 | 操作 | 讲解与预期 |
| --- | --- | --- |
| 0:00–0:45 | 首页展示猫咪；进入「我的 → 首页风格」，依次选择云朵、小狗并返回首页查看，再切回猫咪 | 三套首页有独立构图和入口组织，全部使用原创本地棕色线稿 PNG；账户和订单共享 |
| 0:45–1:25 | 猫咪首页点「门店自取」→「咖啡饮品」→「燕麦热拿铁」 | 商品 ID `p08`；选择 **热 / 大杯（+5 元）/ 半糖**，数量加到 **2**，加入购物车 |
| 1:25–2:05 | 展开购物车查看规格与数量，点击去结算 | 单杯 28 + 5 = 33 元，2 杯商品金额 **66 元**。使用预填演示联系人「林同学」、手机号 `13800138000`，取餐时间「约 20 分钟后」 |
| 2:05–2:35 | 点优惠券，选「午后小确幸券」；填写一条备注后提交 | `coupon-1` 满 25 减 5，自取无费用，实付 **61 元**。订单保存价格与规格快照 |
| 2:35–3:15 | 保持「模拟支付」，先点「模拟支付失败」；在详情继续支付，再点「模拟支付成功」 | 失败后订单仍为待支付，券继续占用；成功后跳转成功页，展示 **61 元**、订单号和 4 位取餐码；没有真实扣款 |
| 3:15–3:50 | 查看订单，在「演示状态推进」依次确认两次 | 制作中 → 待取餐 → 已完成。每次只推进合法一步，完成后奖励 **61 积分**，初始 320 变为 **381**，重复查看不会重复发放 |
| 3:50–4:30 | 「我的 → 演示登录」→「模拟储值」→选择 **100 元**并确认 | 充 100 赠 10，演示余额 **120 → 230 元**；本次未用余额支付，所以金额确定。累计储值从 100 → 200 元，升级 VIP，并产生本金、赠金和余额流水 |
| 4:30–5:00 | 返回「我的」查看余额与积分，切换首页或重新编译 | 展示业务数据保留；一句话说明全部离线本地模拟，正式上线需服务端和微信商户能力 |

如果只剩 3 分钟，可省略第一次支付失败及订单完成推进，保留模板切换、选购、用券、模拟成功、订单详情和储值。

## 适合现场展示的校验

1. 将一杯拿铁加入购物车后，切换为全国邮寄。弹窗列出不兼容商品；先取消，购物车保留；再次切换并确认后仅移除不兼容商品。
2. 外卖结算选择上海地址，界面明确显示超出演示服务区域，不能提交；重选杭州西湖区地址恢复。
3. 点单页「小猫奶油泡芙」为售罄，无法购买。邮寄菜单只显示可邮寄商品。
4. 金额未满门槛时，券面显示还差金额或适用范围原因。取消待支付订单后，原券释放。
5. 「我的 → 积分小铺」用 100 积分兑换满 50 减 10 券；积分记录与券包同时更新。
6. 余额支付可在支付页选择；未登录或余额不足会给出提示，并提供模拟支付与储值路径。

## 建议答辩说明

“这是一款微信原生小程序，不需要真实支付或生产服务器。三套首页共用业务服务，购物车、账户和订单本地持久化。金额以整数分计算，建单和储值有幂等标识，支付和库存写入保持一致；待支付券会占用，取消释放，成功核销。状态推进明确标记为演示，真实商业化需要把身份、资产、订单和库存事务迁移到服务端。”
